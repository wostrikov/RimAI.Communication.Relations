# RimChat 外交 Action 说明

本文档汇总当前 RimChat 外交通信链路中**可触发的全部外交 action**。

说明：

- 下文中的“可触发”不等于“任何时候都能成功执行”。大多数 action 仍受**关系、冷却、在线状态、配置开关、运行时资格校验、参数完整性**等限制。
- 如果AI承诺了某个行为，但是实际未触发，不一定是程序bug，应当考虑是否是模型的幻觉输出。当AI多次未触发某个action时，玩家可以使用命令/指令的口吻描述其意图，或直接使用action名称。
- 除做任务外，无任何需要跨地图的行为。
- 无任何有效延迟承诺，如“我保证明天发送给你”，鉴定为假。
- 个别行为参数受限，如任务无法定制奖励和内容，仅有限类型可选；商队无法指定商品。
- 优先使用行动菜单进行信息发送，相比于自然语言谈判，触发更稳定。
- AI无法识别到你的远征队/火箭空投物品

***

## 一、关系与立场类

### 1. adjust\_goodwill（调整好感度）

- **用途**：调整当前派系对玩家的好感度。
- **主要参数**：
  - `amount`（int，必填）：好感变动值。
  - `reason`（string，可选）：调整原因。
- **触发前提/限制**：
  - 属于直接外交关系变动动作。
  - 受派系独立冷却限制。
  - 代码侧要求 `amount` 可正确解析；缺失或非法会失败。
- **适合场景**：
  - 玩家做出明显善意、恶意、背信、帮助、羞辱等行为后，需要落地到关系数值时。AI按需调整好感度，并不一定必然被触发。

### 2. declare\_war

- **用途**：宣战，使当前派系对玩家进入战争关系。
- **主要参数**：
  - `reason`（string，可选/建议提供）：宣战理由。
- **触发前提/限制**：
  - 仅在关系恶化到允许宣战时使用。
- **适合场景**：
  - 玩家持续威胁、羞辱、勒索或已构成敌对升级时。

### 3. make\_peace

- **用途**：提出和约，尝试结束战争关系。
- **主要参数**：
  - `cost`（int，必填）：议和代价（白银），会进入玩家确认付款流程。
- **触发前提/限制**：
  - 仅在**已处于战争状态**时使用。
  - 默认设计是：只有玩家诚意足够高时才应推进。
  - AI 调用后**不会立刻生效**，而是先弹出确认框。
  - 玩家确认后，系统会从**可交易库存 / 通电轨道信标覆盖物资**中真实扣除对应白银，再正式议和。
  - 玩家取消则不扣银、不改关系，也不会进入议和冷却。
- **适合场景**：
  - 玩家主动求和、表达赔偿意愿、或完成高诚意补偿后。

## 二、支援、访问与贸易类

### 4. request\_aid

- **用途**：请求援助。
- **主要参数**：
  - `type`（string，必填）：`Military` / `Medical` / `Resources`。
- **触发前提/限制**：
  - 只能向**盟友派系**请求。
  - 需要满足对应好感阈值。
  - 有独立冷却。
  - 代码执行器会根据 `type` 映射为不同援助成本类型。
  - 无法指定援军数量，装备等额外参数。
- **适合场景**：
  - 玩家明确请求军事援军、医疗援助、资源援助。

### 5. request\_caravan

- **用途**：请求贸易商队。
- **主要参数**：
  - `goods`（string，可选）：想要的商队/货物方向。
    General 通用
    BulkGoods 批发商
    CombatSupplier 武器供应商
    Exotic 稀有商品
    Slaver 奴隶贩子
- **触发前提/限制**：
  - 仅在**非敌对关系**下使用。
  - 有独立冷却。
  - 无法指定商队人数，指定商品等额外参数。
- **适合场景**：
  - 玩家请求派商队、补给队、交易团来访。

### 6. request\_visitor

- **用途**：请求访客到访。
- **主要参数**：
  - 无必填参数。
- **触发前提/限制**：
  - 仅在**非敌对关系**下使用。
  - 有独立冷却。
  - 无法指定访客人数等额外参数。
- **适合场景**：
  - 玩家希望派系派代表、使者、访问者来殖民地。

### 7. send\_gift

- **用途**：向目标派系发送银币礼物，并提升双方关系。
- **主要参数**：
  - `silver`（int，必填）：礼物银币数量。
  - `goodwill_gain`（int，可选）：预期获得的好感收益。
- **触发前提/限制**：
  - 当前实现只允许发送 **silver**，不支持其他礼物物资。
  - AI 调用后**不会立刻生效**，而是先弹出确认框。
  - 玩家确认后，系统会从**可交易库存 / 通电轨道信标覆盖物资**中真实扣除对应银币，再以礼物形式发送，并提升好感。
  - 玩家取消则不扣银、不加好感，也不会进入送礼冷却。
  - 若库存/信标中的银币不足，确认提交会失败。
- **适合场景**：
  - 当前派系主动示好、奖励玩家、回礼。

## 三、袭击类

### 8. request\_raid

- **用途**：对玩家发起袭击。
- **主要参数**：
  - `strategy`（string）：如 `ImmediateAttack`、`ImmediateAttackSmart`、`StageThenAttack`、`ImmediateAttackSappers`、`Siege`。
  - `arrival`（string）：如 `EdgeWalkIn`、`EdgeDrop`、`EdgeWalkInGroups`、`RandomDrop`、`CenterDrop`。
- **触发前提/限制**：
  - 仅在**当前派系已敌对**时使用。
  - 有独立冷却。
  - 参数会先经过 raid 请求参数规范化。
- **适合场景**：
  - 玩家主动挑衅、要求开战、或敌对派系决定升级冲突。

### 9. request\_raid\_call\_everyone

- **用途**：发动跨派系联合总攻。
- **主要参数**：
  - 无。
- **触发前提/限制**：
  - 属于高强度动作，不是普通 `request_raid` 的别名。
  - 受**全局冷却**与运行时资格校验限制。
  - 会尝试从相关派系中组织联合袭击。
- **适合场景**：
  - 玩家明确说“把所有人都叫来”“联合总攻”“call everyone”“all in”等。
  - 可能招致多派系的参与。

### 10. request\_raid\_waves

- **用途**：发动多波次持续袭击。
- **主要参数**：
  - `waves`（int，必填，2-6）：袭击波次数。
- **触发前提/限制**：
  - `waves` 超出 2-6 会失败。
  - 有派系冷却。
  - 受运行时资格校验限制。
- **适合场景**：
  - 玩家明确要求“连续来几波”“持续施压”“多轮挑战”。

## 四、任务与委托类

### 11. create\_quest

- **用途**：创建任务/委托。
- **主要参数**：
  - `questDefName`（string，必填）：任务模板 Def 名。
  - `askerFaction`（string，可选）：默认当前派系。
  - `points`（int，可选）：任务威胁点数。
- **触发前提/限制**：
  - 必须使用**当前注入审核列表中的合法 questDefName**。
  - 禁止无模板自定义任务。
  - 执行前会经过 `ApiActionEligibilityService` 校验。
  - 某些场景（例如轨道商通信）下，部分地面履约型任务禁止触发。
  - 无法指定任务详细参数，仅支持有限任务类型。
- **适合场景**：
  - 派系向玩家发出正式任务、委托、悬赏、支援请求。

### 12. request\_info

- **用途**：请求补充执行前所需信息。
- **主要参数**：
  - `info_type`（string，必填）：当前只支持 `prisoner`。
- **触发前提/限制**：
  - **不是** **`AIActionExecutor`** **直接执行**，而是由**外交对话专用管线**处理。
  - 当前主要用于囚犯赎金场景，缺少有效目标囚犯 ID 时先补信息。
- **适合场景**：
  - 玩家要谈赎金，但系统还缺少明确囚犯对象时，AI主动请求信息。

### 13. pay\_prisoner\_ransom

- **用途**：提交单次囚犯赎金支付。
- **主要参数**：
  - `target_pawn_load_id`（int，必填）：目标囚犯 ID。
  - `offer_silver`（int>0，必填）：报价银币。
  - `payment_mode`（string，可选）：若提供，仅支持 `silver`。
- **触发前提/限制**：
  - 仅可用于“当前派系所属且仍由玩家关押”的囚犯。
  - 报价参考当前可报价区间，越界时执行前会被夹逼到最近边界。
  - 若自然语言里已经承诺“已支付/已提交赎金”，同条回复必须附带此 action。
  - 无法指定支付模式，仅支持 `silver`。
  - 囚犯超时（>12小时）未释放会导致惩罚。
  - 囚犯释放时健康状态恶化会导致惩罚。
  - 囚犯释放时器官与谈判时相比有缺失会导致惩罚。
- **适合场景**：
  - 外交赎俘谈判进入最终付款提交阶段。

## 五、空投与社交圈类

### 14. request\_item\_airdrop

- **用途**：通过轨道/空投链路即时发送物资。
- **主要参数**：
  - `need`（string，必填）：玩家需求，若玩家说了数量，必须保留数量信息。
  - `payment_items`（array，必填）：付款物资列表。
  - `budget_silver`（int，可选，仅审计，防止不合理订单）。
- **触发前提/限制**：
  - `need`、`payment_items` 必填。
  - 付款物资必须能从通电轨道信标范围内真实扣除。
  - 只支持以一种物品交易一种物品。
- **适合场景**：
  - 轨道商、外交补给、即时物资交换。

### 15. publish\_public\_post

- **用途**：向社交圈/公共舆论发布公开帖子或公开立场内容。
- **主要参数**：
  - 具体参数受社交圈链路和当前 prompt 约束控制。
- **触发前提/限制**：
  - 玩家可以明确要求AI发布公开帖子。
- **适合场景**：
  - 公开宣告、公开谴责、公开表态、对外广播政治立场。

## 六、会话与在线状态类

### 16. exit\_dialogue

- **用途**：结束当前对话，但保持当前在线状态。
- **主要参数**：
  - `reason`（string，可选）
- **触发前提/限制**：
  - 受派系在线状态功能开关控制。
  - 不属于普通外交效果动作，而是会话控制动作。
- **适合场景**：
  - 当前话题自然结束、礼貌收束。

### 17. go\_offline

- **用途**：结束对话并切换为离线状态。
- **主要参数**：
  - `reason`（string，可选）
- **触发前提/限制**：
  - 受派系在线状态功能开关控制。
- **适合场景**：
  - 对方决定暂时离线、不再应答。

### 18. set\_dnd

- **用途**：切换为勿扰状态并停止消息往来。
- **主要参数**：
  - `reason`（string，可选）
- **触发前提/限制**：
  - 受派系在线状态功能开关控制。
- **适合场景**：
  - 明确拒聊、情绪不佳、需要静默一段时间。

### 19. reject\_request

- **用途**：把当前请求明确标记为“拒绝”。
- **主要参数**：
  - `reason`（string，建议填写）
- **触发前提/限制**：
  - 总是允许。
  - 用于**应被记录为正式拒绝**的具体请求。
  - 普通分歧、拖延、模糊回绝不一定要用它。
- **适合场景**：
  - 玩家提出明确请求，而派系要给出正式拒绝结论时。
